# Salmon Review

把自己的 Splatoon 3 打工记录保存到电脑，在浏览器里看搬蛋、巨大鲑鱼击杀、被救援次数和队友表现。

这是一个**本地运行的预发布版**，不是任天堂官方产品。普通玩家从 Release 下载已构建好的安装包即可，安装过程中不需要连接 Docker Hub 或 npm，也无需编译代码。首次打开是空的，需要连接自己的账号，或者导入已有记录。当前没有 AI 分析。

当前版本 **0.3.4**，项目代码采用 **AGPL-3.0-or-later**。已知限制和试用步骤见 [测试说明](BETA_TESTING.md)，版本变化见 [更新记录](CHANGELOG.md)。仓库仍为 Private，Release 附件仅有仓库访问权限的人可下载。

## 开始前先知道这些

- **不需要会编程。** Windows 用户安装 Docker Desktop 后，不用另装 Python、Node.js、nxapi 或 Git。Docker 可以理解成装着本工具运行环境的盒子。
- **电脑负责保存和同步，浏览器负责查看。** 关闭网页不会停止同步；电脑关机、休眠或 Docker 停止时，不能继续采集。
- **一个实例只保存一位玩家。** 不要把自己、朋友和示例账号的数据混在一起。连接另一账号不会自动建立第二份档案。
- **只能下载鱿鱼圈当前还能提供的记录。** 首次连接不能找回全部历史。及时同步，已经归档的场次会留在本机。
- **本地保存不等于全程离线。** 登录和同步要访问任天堂以及 nxapi 使用的第三方认证服务；详情见文末“数据怎么来”。本项目没有接收你的战绩的云端服务器。

## 一、第一次安装（Windows）

### 1. 安装并启动 Docker Desktop

从 [Docker 官方 Windows 安装页](https://docs.docker.com/desktop/setup/install/windows-install/)下载安装程序，按页面核对系统要求，**保留默认设置，按照安装程序提示完成安装即可**。如果提示需要补充系统组件或重启电脑，按提示完成。

本项目可以在 Docker Desktop 的默认 Linux 容器模式下运行，无需为它另外安装 Linux 系统或配置开发环境。如果你已经在使用 Docker Desktop，且它能正常运行 Linux 容器，可以直接跳到下一步。

打开 Docker Desktop，等它显示引擎已经运行（通常是 **Engine running**）。只是下载安装完成，还不算启动成功。

### 2. 下载预构建安装包

1. 打开 [Release 下载页](https://github.com/Awewlife/Salmon-review/releases/tag/v0.3.4)。仓库仍为私有，需要先登录有访问权限的 GitHub 账号。
2. 在 **Assets** 中下载 **`SalmonReview-v0.3.4-windows-x64.zip`**。
3. 将 ZIP **全部解压**到一个固定位置，例如 `D:\Games\SalmonReview`。不要直接在压缩包里运行。
4. 进入能看到 `Start.cmd`、`Start.ps1`、`compose.yaml` 和 `salmon-review-image.tar.gz` 的文件夹。

**不要选页面自动生成的 “Source code (zip)” 或仓库的 Code → Download ZIP。那些是开发源码，不包含镜像，不能按本安装流程直接使用。** 当前安装包适用于 Intel / AMD 64 位 Windows 电脑；ARM 电脑暂未提供对应包。

### 3. 双击启动

确认 Docker Desktop 已显示引擎运行，然后双击 **`Start.cmd`**。它会：

1. 检查 Docker 状态和安装包校验值。
2. 自动导入随包提供的完整镜像，已导入同一版本时跳过。
3. 启动服务并等待就绪，自动打开浏览器。

整个过程不运行 build，不下载 Node 或 npm 依赖。导入镜像需要一些时间和磁盘空间，请等到“启动成功”。如果失败，窗口会保留错误提示，请按第六部分排查。脚本不需要管理员权限；启动器只为当前 PowerShell 进程设置执行方式，不修改全局执行策略。受组织策略限制时可以使用下面的手动方式。

> **旧版本用户：先备份并沿用原项目名！** 默认项目名为 `salmon-review`。如果原来用 `salmon-review-dev` 等其他名字，请在解压目录的终端执行 `./Start.cmd -ProjectName 原项目名`。脚本检测到其他旧数据卷时会提醒，不会悄悄改用空库。项目名可以在 Docker Desktop 的 Containers 列表查看。

不使用启动器时，也可以在本目录终端执行：

```powershell
docker load -i salmon-review-image.tar.gz
docker compose -p salmon-review up -d --no-build --pull never
docker compose -p salmon-review ps
```

看到 `app` 处于 `Up` / `running`，稍后变为 `healthy`，表示服务已经启动。`SHA256SUMS.txt` 可用于手动检查文件完整性；校验值用于发现损坏，不替代从本仓库 Release 下载的来源确认。

### 4. 在浏览器打开

打开 **[http://127.0.0.1:8787/](http://127.0.0.1:8787/)**。这是你自己电脑上的地址，不是外部网站。不要直接双击项目里的 `index.html`。

第一次显示“尚未导入记录”是正常的。接下来连接账号，或者跳到“导入已有文件”。

> Linux x86-64：可用 Docker Engine + Compose 插件，在解压目录按上面的手动命令导入并启动。Windows 启动脚本不适用于 Linux。macOS / ARM 平台暂不提供已验证的安装包。

## 二、连接账号并取得第一批记录

准备好**你玩 Splatoon 3 时使用、能够在鱿鱼圈查看打工记录的任天堂账号**。如果官方应用本身也打不开记录，请先处理账号或官方服务的问题。

1. 点击页面顶部的 **“未连接账号”**，会直接打开连接区域。也可以从左侧 **“数据与同步”** 进入。
2. 点击 **“开始连接 / 重新连接”**，等待生成链接，再点击 **“打开任天堂登录页面”**。
3. 在任天堂页面完成登录。密码和验证码只在任天堂页面输入，本工具不索要密码。
4. 出现 **“选择此账号”**（英文可能是 **Select this person**）时，在这个按钮上**点鼠标右键 → 复制链接地址 / 复制链接**。
5. 回到 Salmon Review，把复制的链接粘贴到输入框，点击 **“完成连接”**。正确的链接以 `npf71b963c1b7b6d119://auth` 开头。
6. 看到连接成功后，点击页面顶部或管理窗口内的 **“立即同步”**。等待完成，页面会自动更新。

**最容易出错的地方：要复制“选择此账号”按钮的链接，不是地址栏的网址，也不要直接左键点击按钮。** 网页里有操作示意。返回链接相当于临时登录凭证，只粘贴回本机工具，不要发到聊天、截图或 Issue 中。

每次生成的登录链接有效期约 10 分钟。过期、误点跳转或登录失败时，重新生成并使用新的页面。重试会立即清除上一次的失败提示；验证期间请等待，不要重复点击。

无需申请开发者资格，无需配置 `NXAPI_AUTH_CLIENT_ID`，也不需要安装 s3s。容器使用自己的登录缓存，不会自动读取你之前在 Windows 上给 nxapi 或 s3s 登录留下的文件。

## 三、平时怎么用

### 同步和查看

- 打完几场后，点击顶部 **“立即同步”**。同步进行中会显示状态，按钮暂时不可重复点击。
- 默认关闭自动同步。在“数据与同步 → 同步设置”可选每 15 / 30 / 60 / 120 分钟同步。
- 手动同步完成后等待 **5 秒**即可再次操作；普通网络失败或任务中断也只需等 5 秒，按钮会显示倒计时。任务仍在运行时不能重复启动。
- 自动同步在网络失败后按 5、10、20 分钟等逐步延后（最长约 5 小时 20 分钟），同时遵循你选择的同步间隔；手动重试不受这段自动等待时间限制。
- 明确收到限流时，手动和自动同步都必须等到提示时间（至少 15 分钟，上游要求更久则按更久的时间）。重新连接账号也不会清除这段限流等待。
- 登录失效时会显示 **“重新连接账号”** 入口并暂停同步。连接成功后即可同步；若仍有限流等待，则继续遵守该时间。
- 排班总览能看本期均值、趋势和所有已保存场次。点击场次看波次、队员和巨大鲑鱼明细；点击“查看详细趋势”可查看三项独立趋势、对比疑似组队队友并导出图表。
- 所有时间统一按 **UTC+8** 展示。同步不会把旧场次替换掉，重复记录会自动跳过。

“账号已连接”表示本机保存了登录状态，**不代表此刻一定能成功获取新数据**。仍要看“上次成功同步”的时间；登录过期或上游服务异常时，按提示重新连接或稍后再试。

### 选择一段趋势并导出图片

1. 在排班总览点击 **“查看详细趋势”**。
2. 展开默认收起的 **“场次筛选与导出”**，选择起始和结束场次。
3. 可加入疑似组队队友、取消部分队友，或关闭图中的人名。
4. 选择搬蛋、击杀、被救援中的一张图，或全部三张图，点击 **“导出 PNG”** 或 **“导出 SVG”**。导出会保留所选区间的坐标轴；搬蛋折线不计协助。

三张图可以横向同步滚动。队友缺席或原始记录存在缺口时，折线和连续同队判断都会断开；中断场次单独说明，不算作普通结算场次缺失。

读取同步状态或新战绩时，已有页面会保留。相同标签页刷新时先展示上次成功读取的战绩，顶部注明正在更新；第一次打开仍需读取。浏览器临时缓存只包含展示数据，没有登录凭据，不能代替数据卷备份。

### 停止与下次启动

关闭网页即可结束查看。想停止后台运行，在项目文件夹的终端执行：

```powershell
docker compose -p salmon-review stop
```

下次先打开 Docker Desktop，再执行：

```powershell
docker compose -p salmon-review up -d --no-build --pull never
```

然后打开同一个本机网址。停止或重建容器不会清空已保存记录。

## 四、导入已有文件（不登录也能用）

如果已经用 nxapi 导出过记录，在“数据与同步 → 导入已有记录”选择 JSON 文件，可多选：

| 文件名 | 用途 |
| --- | --- |
| `splatnet3-coop-result-*.json` | 每场打工的详细结算 |
| `splatnet3-coop-summary-*.json` | 排班与场次列表，用于把记录归到正确的那期工 |

尽量两类一起导入。只有详情也能先保存，补上汇总后再归类。先后顺序不限，重复导入会去重。

这里**不能直接导入观星教程里的 `gear.json`**：那是装备数据，不是打工结算。s3s 的其他导出格式也不保证兼容。

每批最多 2000 个 JSON，总计建议小于 60 MB；较多记录请分批选择。关键字段缺失或不支持的模式会列在“暂未纳入统计的记录”里，不会当成零分。

`examples/` 有完全虚构的演示记录。不要导入准备用于自己账号的实例，否则它会先绑定演示玩家。普通玩家直接登录自己的账号即可，无需导入示例。

## 五、备份、换电脑和升级

### 备份与恢复

在“数据与同步 → 备份与恢复”点击 **“下载数据备份”**，保存下载的 JSON 文件。建议更新程序前、迁移电脑前，以及平时隔一段时间备份一次。

备份包含原始战绩、排班汇总和玩家昵称，**不包含登录凭据、自动同步设置和图片缓存**。请自己保存，不要公开上传。

换电脑时：按第一部分安装 → 在新页面选择备份 → 点击 **“恢复并合并”** → 重新连接同一个任天堂账号 → 按需重新设置自动同步。恢复只增加缺少的记录，不覆盖现有记录。网页恢复同样有约 60 MB 的大小限制，超大的单个备份目前不能从网页恢复。

### 更新版本

同一台电脑更新时，**不需要导出后再导入战绩**：程序在镜像中，战绩与登录缓存保存在独立的数据卷里。使用相同的项目名启动新版，会自动沿用旧数据；升级前下载备份只是留一份保险。更换电脑或更换数据卷时才需要恢复备份。

先下载备份，并记住原来的项目名称和端口。更新时必须继续使用它们。

下载新版 Release 中的 **windows-x64.zip 安装包**，全部解压到新文件夹。复制旧 `.env`（如果有），双击新版 `Start.cmd`；旧项目使用自定义名称时，仍运行 `./Start.cmd -ProjectName 原项目名`。脚本会导入新版镜像并重建应用容器，继续使用同名数据卷，战绩和登录状态保留。

如果以前使用自定义端口，可以复制旧 `.env`，或运行 `./Start.cmd -ProjectName 原项目名 -Port 8788`；`-Port` 只作用于这次启动命令，以后重启继续传同一端口，或在 `.env` 中保存 `SALMON_PORT=8788`。

不要通过改项目名来解决升级问题，也不需要执行 `git pull`、`npm install` 或 `docker compose build`。开发者源码构建见文末。

完成后刷新浏览器；如果仍显示旧界面，按 `Ctrl + F5` 强制刷新。

**不要删除 Docker Desktop 的数据卷（Volumes），不要使用 `docker compose down -v`，也不要在没有备份时重置 Docker Desktop。** 这些操作可能删除战绩和登录状态。程序文件夹和数据卷是两回事，单独复制程序文件夹不算备份。

## 六、常见问题

| 看到的情况 | 应该怎么做 |
| --- | --- |
| v0.3.3 导入镜像后提示“与发布版本不符” | 下载 v0.3.4 或更新安装包，完整解压后沿用原项目名启动。这是旧启动器兼容性问题，无需重装 Docker、删除镜像或数据卷。 |
| 提示找不到 `docker` 命令 | 确认 Docker Desktop 已安装，重新打开终端后再试。 |
| `Cannot connect to the Docker daemon`、pipe 或 engine 错误 | 打开 Docker Desktop，等待引擎运行；如果 Docker Desktop 自身报错，先按它的提示或官方安装说明完成修复，再运行本项目。 |
| 提示找不到配置文件 | 终端没有开在项目目录。进入能看到 `compose.yaml` 的文件夹。 |
| 出现 `npm ci`、Docker Hub 超时或正在 build | 你可能下载了源码包或使用了旧命令。普通玩家应下载 Release 的 windows-x64 安装包并运行 Start.cmd；安装器不会下载这些依赖。 |
| 找不到镜像包或校验失败 | 重新下载完整 windows-x64.zip 并全部解压，不要混用不同版本的 compose.yaml、release.json 或镜像文件。 |
| 提示镜像不存在 / pull policy never | 先用 Start.cmd 导入镜像，或者执行 docker load -i salmon-review-image.tar.gz。无需登录 Docker Hub。 |
| 提示发现已有项目 | 使用 Start.cmd -ProjectName 原项目名，避免误开空库。 |
| `port is already allocated`、端口被占用 | 可能另一份 Salmon Review 已在运行。先在 Docker Desktop 查看；如需换端口，按下方说明设置。 |
| 浏览器打不开 | 确认地址是 `http://127.0.0.1:8787/`，运行 `docker compose -p salmon-review ps` 查看是否已启动。不要用 `https`，也不要直接打开 HTML 文件。 |
| 页面只剩文字、样式没加载 | 先按 `Ctrl + F5`。还不正常时，重新构建当前版本并检查容器状态。 |
| 复制的登录链接不对 / 已过期 | 重新生成登录链接，在任天堂页面的“选择此账号”按钮上右键复制；不要复制地址栏。 |
| `Remote configuration prevents Coral authentication` / f-generation 服务不可用 | 是上游认证限制或故障，不一定是密码错误。稍后重试或关注 nxapi 的更新，不要反复改密码。 |
| 账号已连接，但同步失败 | 连接状态是本机缓存状态。查看具体提示：认证失效时重新连接，网络 / 限流时等到允许时间再试。 |
| 更新后突然没有记录 | 先核对 Compose 项目名是否变了；新名字会对应空数据卷。不要删除旧卷，回到原项目名运行或恢复备份。 |
| 提示账号与已有战绩不一致 | 当前实例已经绑定另一位玩家。连接正确账号；不要把多位玩家或示例记录混用。 |
| 场次少于自己实际打过的数量 | 上游只提供近期记录，未及时采集的旧场次可能无法补回；另检查“暂未纳入统计的记录”。 |
| 手机 / 朋友的电脑打不开这个网址 | 正常。`127.0.0.1` 指向正在打开网页的那台设备。此版本只供安装它的电脑使用。 |

**更换端口：** 在项目文件夹打开终端，执行 `Copy-Item .env.example .env`（已有 `.env` 就直接编辑，不要覆盖）。用记事本将其中 `SALMON_PORT=8787` 改为 `SALMON_PORT=8788`，保存后重新运行构建命令，改为打开 `http://127.0.0.1:8788/`。数据仍在原项目的数据卷中。

排查运行问题可以执行：

```powershell
docker compose -p salmon-review logs --tail=100 app
```

程序只输出经过筛选的运行日志。反馈问题时写明系统、版本、操作步骤和错误提示；**不要附带授权返回链接、登录缓存或整个数据卷**。截图中的玩家昵称也可以先遮住。

## 数据怎么来，以及用了谁的工具

如果你用过观星，可以这样理解：先授权工具读取自己的鱿鱼圈数据，再按需要取出不同内容。观星常用的是装备信息；本工具获取的是**打工结算**，不会预测种子、控制游戏或修改游戏存档。

流程是：**任天堂账号登录 → nxapi 处理认证 → 读取 SplatNet 3（鱿鱼圈 3）打工记录 → 下载为 JSON → 本机归档 → 网页统计展示**。

| 组件 / 服务 | 在本项目中负责什么 |
| --- | --- |
| Nintendo / SplatNet 3 | 打工记录的原始来源；游戏图片也来自记录引用的 Nintendo 资源域名。 |
| [nxapi](https://github.com/samuelthomas2774/nxapi) `1.6.1-next.257` | 社区开发的非官方工具。容器调用它发布在 npm 的原始命令行程序，完成登录、凭据缓存、令牌刷新和记录下载。这里的“原始发布包”指 nxapi 项目发布，并非任天堂官方软件。 |
| nxapi 的远程配置与第三方认证服务 | 协助完成 Nintendo Switch Online 认证所需的 f-generation 步骤。依赖版本内置的服务地址包括 `nxapi-znca-api.fancy.org.uk`，实际选择由 nxapi 的远程配置控制，可能变化或暂停。说明见 [nxapi 认证文档](https://github.com/samuelthomas2774/nxapi#coral-client-authentication)。 |
| [Node.js](https://nodejs.org/) 22.23.2、内置 SQLite | 运行本地服务、保存原始记录与统计所需数据。SQLite 可以理解为电脑里的档案库。 |
| [undici](https://github.com/nodejs/undici) 6.28.1 | 随应用安装的 HTTP 网络请求库，也是 nxapi 的依赖；普通玩家无需单独配置。 |
| [Docker / Compose](https://docs.docker.com/) | 打包并运行上述环境，管理后台程序和数据卷。 |

本项目运行时**不调用 s3s，不调用观星教程网站的接口，也不调用 Cypas/splatoon3-nso 的登录服务**。登录引导借鉴了 [Cypas/splatoon3-nso](https://github.com/Cypas/splatoon3-nso) 的说明方式；页面示意由本项目绘制，认证实现仍交给 nxapi。

### 哪些数据会离开电脑？

- 任天堂登录页面处理账号密码和验证码。Salmon Review 接收的是你复制回来的授权链接，用它完成本机认证。
- nxapi 会把认证需要的**短期令牌、账号标识等必要字段**发送给其第三方认证服务。这意味着认证需要信任该服务，不能表述为“只与任天堂通信”。服务选择和具体字段以所固定 nxapi 版本及其远程配置为准。
- 同步请求会发送到任天堂；首次显示游戏图片时会从 Nintendo 资源域名下载 PNG 并缓存。已经归档的文字和统计可以在没有上游网络时查看，但本地服务仍需运行。
- 本项目没有战绩上传服务器，不自动把记录上传到 stat.ink、观星网站或 AI 服务。当前也没有接入 LLM。
- 构建镜像时还要从 Docker 镜像仓库与 npm 下载软件依赖，这和任天堂账号登录是两个独立步骤。

### 本机存放了什么？

数据位于 Docker 的命名卷 `salmon-data`，实际名称带项目名前缀。按本教程运行时通常为 `salmon-review_salmon-data`，在容器内挂载到 `/data`。

其中有 SQLite 数据库、原始记录、`/data/exports/` 的下载文件、图片缓存，以及 `/data/nxapi/` 的登录缓存。**登录缓存有访问权限限制，但没有额外加密**，能读取数据卷的人也能读取它；不要把完整数据卷当作普通战绩包分享。退出账号会清除登录缓存并关闭自动同步，已保存战绩仍保留。

默认只监听宿主机的 `127.0.0.1`。当前没有供公网使用的用户注册、访问权限隔离等功能，不支持直接作为多人网站发布，也不支持开放到公网 / 局域网或套反向代理供多人共用。

### 数字如何计算？

- 搬蛋与“+ 协助”分开；折线与搬蛋均值不计协助。
- “击杀”专指巨大鲑鱼。团队击杀取敌人明细中的击倒数合计。
- “被救援次数”来自个人结算，不等于全部倒地次数。
- “通过”指常规三波通过，头目加赛另计；平均通过波次不含加赛。
- 当前主要统计常规 `REGULAR` 打工，含头目加赛。其他模式或缺少关键字段的记录保留原始数据并说明排除原因。
- 趋势详情中的“场次筛选与导出”默认折叠，标题旁显示当前范围；展开后支持选择起始、结束场次，预览后导出 PNG 或 SVG；可导出单项或全部三张图的长图。导出保留原场次编号、当前选择的队友、人名开关、通过标记及断线，不包含范围外的数据。
- 保存完整性与能否统计分开判断：无波次且结果代码为 -1 的中断记录单独保存，不占正常场次数，也不作为零值参与均值。其他结算字段不全的记录注明暂不统计。中断前后不推断连续同队。
- 整期记录不完整时，仍在原始列表确认连续的片段内识别“连续同队 ≥ 3 场”。中间缺失详情、排除的场次或无法确认相邻关系时断开计数与对比折线；按玩家身份而非昵称识别，仍然只能称为疑似组队。
- “裤裆藏大”表示常规失败且能够确认有特殊武器未用完，不等于断言这个人导致了失败。
- 游戏结算中的团队搬蛋与个人合计可能有原始差异；本工具保留各自口径，不擅自改成相等。

## 给开发者与准备再发布的人

普通玩家可以跳过本节。源码仓库的默认 `compose.yaml` 也只运行预构建镜像，不包含 build。开发者下载源码后使用单独的构建配置：

```powershell
docker compose -p salmon-review-dev -f compose.yaml -f compose.build.yaml up -d --build
```

构建仍需要联网；Dockerfile 为 npm 设置持久缓存及请求重试，减少中断后的重复下载。缓存无法解决下载站点始终不可达的问题。

维护者发布流程：提交并通过 CI → 创建并推送 `v版本号` 标签 → 在 Actions 手动运行 **Package private prerelease**，输入已存在的标签。流程会构建、测试、打包、验证空数据启动，附上镜像、项目源码和第三方材料，再创建预发布 Release。它不改变仓库可见性，也不会上传本机数据卷。

也可按同样步骤在本机构建，镜像标签为 `salmon-review:版本号`，传入 `--build-arg VCS_REF=提交完整SHA`，再用 Python 3.11+ 运行 `scripts/package-release.py --output 仓库外的空目录`。脚本要求干净提交与镜像标记一致，使用从未启动的临时容器收集软件声明。

运行命令分别为 `nxapi nso auth --select` 和 `nxapi splatnet3 dump-results <目录> --coop --no-battles --auto-update-session`。本项目不提取 nxapi 的客户端 ID 重写认证流程，也不自行换取令牌。授权返回链接经后端校验 `state` 后通过标准输入交给 CLI，不进入命令参数；原始 CLI 输出被截获，不回传网页或直接写入应用日志。

CLI 没有独立采集语言选项。本项目的进程预加载适配器将 SplatNet 3 数据请求的 `Accept-Language` 固定为 `zh-CN`，不更改任天堂账号语言或地区，不改写 nxapi 认证逻辑。旧的繁体原始记录不会仅因升级自动重写。

每个实例同一时间只运行一个同步；导入、恢复和退出账号不能与同步同时进行。任务最长 15 分钟，重启后将未结束任务记为中断。已完成下载的 JSON 持续归档，未完成文件改名保留，下次重试续传；认证异常可能暂停自动同步，请求受限会延后重试。

数据库 schema 当前为 v1。遇到高于当前程序支持版本的数据库时拒绝启动，避免降级覆盖；后续 schema 升级需提供显式迁移和测试。

开发环境使用 Node 22.23.2；这个版本的内置 SQLite 仍带 experimental 标记。安装依赖并运行：

```sh
npm ci --ignore-scripts
npm test
npm run check
npm start
```

`DATA_DIR` 指定数据目录，`PORT` 指定端口。直接运行默认监听 `127.0.0.1`；容器内监听 `0.0.0.0`，由 Compose 限制宿主机访问范围。
