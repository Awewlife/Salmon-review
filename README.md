# Salmon Review · 本地 Docker 开发预览

Splatoon 3 打工数据复盘工具。运行在自己的电脑上，浏览器负责展示，Node 后端负责导入、归档与同步，SQLite 保存历史记录。首版隐藏 AI 入口。

## 启动

安装并启动 Docker Desktop（Linux 容器），下载或克隆本仓库，在仓库目录运行：

```sh
docker compose up -d --build
```

打开 http://127.0.0.1:8787/ ，点击“数据与同步”。首次启动为空库，不附带真实玩家战绩。Windows 原型用户无需另外安装 Node、Python 或 nxapi。

默认端口只绑定本机 IPv4 回环地址。此版本不支持通过公网、局域网或反向代理提供多用户服务。

## 先用文件导入

在“数据与同步”中多选 nxapi 的 `splatnet3-coop-result-*.json` 与 `splatnet3-coop-summary-*.json` 文件。可分批导入，先后顺序不限。缺少汇总的详情先保留、后归类。重复场次跳过，不覆盖已归档原始记录。

`examples/` 中有完全虚构的一场记录和汇总，可在空实例上体验导入。一个数据卷只支持一位玩家；导入示例后若要导入自己的账号，应使用另一个 Compose 项目，例如 `docker compose -p salmon-personal up -d --build`，同时用不同宿主端口，或者先停止示例实例。不要把测试样例与自己的记录混在同一数据卷里。

网页每批最多 2000 个 JSON，总计建议不超过 60 MB（服务端上限 64 MB）。备份恢复同样受字节大小限制；超大历史库还需要后续的流式导入能力。

## 账号连接与在线同步

本版直接调用 npm 官方发布的 nxapi 命令行，使用其自带的客户端配置、登录缓存与令牌刷新机制。无需注册客户端，也无需配置 `NXAPI_AUTH_CLIENT_ID`；容器不读取宿主机 nxapi 的登录缓存。

1. 页面点击“开始连接”，打开任天堂账号页面。
2. 登录后复制“选择此账号”按钮的授权链接，粘贴回本机窗口，点击“完成连接”。授权链接只通过本机后端的标准输入交给正在等待的 nxapi 进程，不放入命令参数或日志；10 分钟未提交则过期。
3. 连接完成后点击“立即同步”。可选 15/30/60/120 分钟自动同步，默认关闭；只有容器运行时才会执行。
4. 更换登录时会先使用独立临时目录；认证成功后再替换旧登录，失败保留旧登录。每个实例仍然只接受同一位玩家的战绩。

内部运行的是 `nxapi nso auth --select` 和 `nxapi splatnet3 dump-results <目录> --coop --no-battles --auto-update-session`。应用调用发布包的原始 CLI 入口，不提取其客户端 ID 注入自己的 API 客户端，也不自行换取或刷新令牌。原始命令输出可能包含令牌，因此由后端截获并丢弃；网页只收到授权网址、进度和脱敏错误。

从旧的独立认证客户端版本升级后，需要在网页重新连接一次。旧凭据不会自动转换；退出账号时一并清理旧版凭据文件，战绩与备份保持兼容。

CLI 没有独立语言选项，本项目通过进程预加载适配器将 SplatNet 3 数据请求的 `Accept-Language` 固定为 `zh-CN`，不修改任天堂账号地区或语言，也不改写 nxapi 的认证逻辑。认证过程仍依赖 nxapi 的第三方 f-generation 服务，会向该服务发送短期认证令牌。参考 https://github.com/samuelthomas2774/nxapi#coral-client-authentication 。不能保证上游接口或认证服务长期可用。

## 数据与同步规则

- 一个实例只保存一位玩家的战绩，按稳定玩家身份校验；混合账号的整批导入会被拒绝。
- 场次按原始 ID 去重。SQLite 同时存储完整原始详情、汇总和排班归属。之前保存的场次不会随上游最新列表变化而消失。
- 排班用模式和完整起止时间标识。缺少汇总的记录不会仅凭地图或日期被猜测分组。
- 常规 REGULAR 打工（含头目加赛）参与统计；其他模式和关键字段缺失的记录保留，在数据管理中说明排除原因。
- 搬蛋与协助分开；巨大鲑鱼团队击杀取敌人明细合计；被救援不等同所有倒地。
- 通过指常规三波通过，不受头目结果影响。通过波次按失败波次计算，不含加赛。
- 本期记录不完整时，不推断连续同队关系。记录完整时按稳定玩家 ID 判断，改名和同名不会混淆。
- “裤裆藏大”只用于常规失败且特殊武器使用能唯一归属的情况，不表示已经判断失败原因。
- 同步为独立子进程任务；关闭网页不影响任务。每个实例只允许一个同步，导入/恢复/退出账号不能与同步同时进行。
- 已下载完成的 JSON 每隔约半秒检查并归档；中断后重试会跳过已有记录。网络失败保留已下载文件并退避，下次同步复用这些文件；CLI 不提供结构化 Retry-After，请求受限时至少等待一小时再尝试。认证失效或上游禁止认证会暂停自动同步。
- 自动同步默认为关闭；手动同步有最少一分钟间隔，失败后有更长等待。任务超时上限为 15 分钟，服务重启时把未结束任务记为中断。
- 游戏 PNG 图片在首次浏览时从导出记录引用的 Nintendo 资源域名缓存到本机，首次加载需要网络；没有图片时统计仍可使用。

## 数据卷、备份和升级

Compose 命名卷 `salmon-data` 挂载到 `/data`，实际卷名包含 Compose 项目前缀。数据库、图片缓存和独立凭据文件保存在其中。停止或重建容器不会清除卷。

“下载数据备份”生成包含原始战绩与汇总的 JSON，不包含登录凭据、自动同步设置和图片缓存。可在同账号或空实例中“恢复并合并”，重复记录跳过。备份包含玩家昵称，应按个人数据保管。nxapi 原生登录缓存存放于 `/data/nxapi/` 的受限目录，不额外加密；能访问数据卷的人也能读取缓存，不能公开分享该目录或完整数据卷。CLI 导出 JSON 留在 `/data/exports/` 用于断线续传。未写完的 JSON 会改名保留，以便下次重新下载。退出账号删除登录缓存，保留已导出与已归档战绩。

升级前先下载备份，然后：

```sh
git pull
docker compose up -d --build
```

当前数据库 schema 为 v1，首次运行在事务中初始化；检测到高于当前支持版本的数据库会拒绝启动，不降级覆盖。未来升级 schema 必须添加显式迁移、迁移前备份与对应测试。

停止：`docker compose stop`。查看状态：`docker compose ps`。查看脱敏运行日志：`docker compose logs --tail=100 app`。不要在保留数据时使用带 `-v` 的删除命令。

## 开发和验证

需要 Node 22.19.0 或兼容的 Node 22 版本；当前使用 Node 内置 SQLite（该版本标为 experimental），容器固定相同运行时。

```sh
npm ci --ignore-scripts
npm test
npm run check
npm start
```

`DATA_DIR` 指定本地数据目录，`PORT` 指定端口；直接运行默认监听 127.0.0.1。容器内部监听 0.0.0.0，但 Compose 只在宿主机开放 127.0.0.1。

自动测试覆盖空库、先详情后汇总、跨期保留、去重、混合账号事务回滚、缺字段排除、原始数据备份恢复、特殊武器规则、同名/改名、CLI 登录持久化、来源检查、后台任务互斥、断线续传、退避暂停和授权 state 校验。

此版本是可运行的本地开发预览，还不是经过其他玩家独立安装验收的正式发行版。项目许可、完整依赖声明、新账号在线认证验收，以及更多实际特殊模式样本仍需在发布镜像前完成。不会自动上传战绩到本项目服务器。

原始静态原型保存在 Git 提交 `15efce3`。`scripts/collect-data.mjs` 与 `scripts/build-data.py` 为旧原型开发工具，Docker 版不调用它们。
