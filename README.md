# Salmon Review

Salmon Review 是一个本地运行的 Splatoon 3 鲑鱼跑记录与复盘工具。它将打工记录保存在电脑上，并通过浏览器展示个人表现、队友对比和段位分数变化。

当前版本：**0.3.12 · 私有预发布版**。本项目不是任天堂官方产品。下载发行版需要具有仓库访问权限的 GitHub 账号。

[下载发行版](https://github.com/Awewlife/Salmon-review/releases/tag/v0.3.12) · [更新记录](CHANGELOG.md) · [测试说明](BETA_TESTING.md) · [网页更新说明](UPDATING.md)

## 功能概览

| 功能 | 说明 |
| --- | --- |
| 排班总览 | 查看地图、配发武器、通过率、个人场均表现和已保存场次。 |
| 对局详情 | 查看波次结果、队员表现、巨大鲑鱼明细和特殊武器使用情况；点击队员名称可查看本场名片与工服。 |
| 表现趋势 | 查看搬蛋、巨大鲑鱼击杀和被救援次数，可在“更多图表”中开启红蛋图；支持数量／占比切换、队友对比、团队合计和 25% 参考线。 |
| 分数变化 | 展示每场结束时的段位分数；跨段位时使用连续的分层刻度，单一段位时自动缩放。 |
| 图表导出 | 按场次范围导出分项趋势图，或导出本期分数图；支持带图例的 PNG 和 SVG。 |
| 本期个人纪录 | 查看最高段位分数、单场个人搬蛋、巨大鲑鱼击杀和最长连胜，并跳转到对应场次。 |
| 数据管理 | 支持手动／定时同步、nxapi 文件导入、备份和恢复。 |
| 维护工具 | 支持主程序与更新组件的网页更新、本机诊断和诊断信息导出。 |

分项趋势图支持同步定位场次和横向滚动。“更多图表”中的红蛋图默认隐藏，导出时可独立勾选四张图表中的任意组合，并拖动调整排列顺序。浏览器会保存图表显示偏好、导出选择和顺序；重新打开趋势详情时恢复全部场次，不保留队友选择和场次筛选。

### 使用范围

- 每个实例只保存一位玩家的记录。连接其他账号不会创建独立档案。
- 同步只能获取鱿鱼圈当前提供的记录，不能补回所有历史场次。已归档记录保留在本机。
- 关闭网页不会停止后台服务。电脑关机、休眠或 Docker 停止时，同步也会停止。
- 登录、同步和首次加载图片需要网络。已保存的记录可在本地服务运行时离线查看。
- 当前主要统计常规打工（`REGULAR`），包括头目加赛。其他模式和不完整记录的处理见文末。
- 本项目不提供 AI 分析，也不自动上传战绩到云端。

## 一、首次安装（Windows）

### 1. 准备运行环境

安装包适用于 **Intel / AMD 64 位 Windows 电脑**。请先按 [Docker 官方安装说明](https://docs.docker.com/desktop/setup/install/windows-install/)核对系统要求。

使用 Docker Desktop 的 Linux 容器模式，通常保持默认设置即可。建议使用默认的 WSL 2 后端；如果提示 WSL 缺失或版本过低，请按提示安装或更新。无需另行安装 Ubuntu 等 Linux 发行版。

1. 安装 Docker Desktop。
2. 按安装程序提示完成系统组件安装或重启。
3. 打开 Docker Desktop。
4. 确认使用 Linux 容器模式，并等待引擎显示运行状态（通常为 **Engine running**）。

安装包已包含程序运行环境，无需另装 Python、Node.js、nxapi 或 Git。导入程序镜像时不需要访问 Docker Hub 或 npm。

### 2. 下载并解压

1. 登录有仓库访问权限的 GitHub 账号。
2. 打开 [v0.3.12 发行版页面](https://github.com/Awewlife/Salmon-review/releases/tag/v0.3.12)。
3. 在 **Assets** 中下载 **`SalmonReview-v0.3.12-windows-x64.zip`**。
4. 将 ZIP 完整解压到固定目录，例如 `D:\Games\SalmonReview`。
5. 确认目录中包含 `Start.cmd`、`Start.ps1`、`compose.yaml` 和 `salmon-review-image.tar.gz`。

不要在压缩包内直接运行。GitHub 自动生成的 **Source code (zip)** 和 **Code → Download ZIP** 不包含程序镜像，不能用于本安装流程。

### 3. 启动程序

首次安装使用默认项目名 `salmon-review`。**已有版本的用户应先阅读第五部分，沿用原项目名和端口。** 项目名决定使用哪一组数据卷，可在 Docker Desktop 的 **Containers** 列表查看。

1. 确认 Docker Desktop 的引擎已运行。
2. 双击 **`Start.cmd`**。
3. 等待启动器显示“启动成功”。

启动器会校验安装文件、导入镜像、启动服务并打开浏览器。同一镜像已导入时会跳过导入。失败时，窗口会保留错误提示。

启动器无需管理员权限，也不修改全局 PowerShell 执行策略。

### 4. 打开本地页面

如果浏览器未自动打开，请访问 **[http://127.0.0.1:8787/](http://127.0.0.1:8787/)**。这是当前电脑的本地地址。不要直接打开项目中的 `index.html`。

首次使用时没有战绩。请连接自己的任天堂账号，或按第四部分导入已有记录。

Linux x86-64 用户可使用 Docker Engine 和 Compose 插件，按文末命令手动启动。Windows 启动器不适用于 Linux。macOS 和 ARM 平台暂未提供已验证的安装包。

## 二、连接账号并同步记录

使用能够在鱿鱼圈查看打工记录的任天堂账号。若官方应用也无法读取记录，请先解决账号或官方服务的问题。

1. 打开 **数据与同步**，或点击页面顶部的 **未连接账号**。
2. 点击 **开始连接 / 重新连接**。
3. 链接生成后，点击 **打开任天堂登录页面**。
4. 在任天堂页面完成登录。
5. 在 **选择此账号**（**Select this person**）按钮上单击鼠标右键。
6. 选择 **复制链接地址**。
7. 返回 Salmon Review，将链接粘贴到输入框。
8. 点击 **完成连接**，等待验证结果。
9. 连接成功后，点击 **立即同步**。

**复制按钮链接，不要复制地址栏网址。** 正确的返回链接以 `npf71b963c1b7b6d119://auth` 开头。该链接属于临时登录凭据，只应粘贴到本机工具。

密码和验证码只在任天堂页面输入。登录链接有效期约 10 分钟；过期后请重新生成。验证期间请等待，不要重复提交。

无需申请开发者资格或配置 `NXAPI_AUTH_CLIENT_ID`。程序使用独立的登录缓存，不读取 Windows 上其他 nxapi 或 s3s 安装的登录文件。

## 三、日常使用

### 同步与查看

点击 **立即同步** 获取近期记录。自动同步默认关闭，可在 **数据与同步 → 同步设置** 中选择 15、30、60 或 120 分钟间隔。

同步任务运行时不能重复启动。手动同步完成或普通网络错误后，等待 5 秒可重试。自动同步遇到网络错误时会延后重试。收到上游限流提示时，手动和自动同步均需等待页面显示的时间。

“账号已连接”仅表示本机保存了登录状态。请通过 **上次成功同步** 时间确认采集结果。登录失效时，按提示重新连接账号。

在排班总览选择排班。点击列表中的场次或总览图中的节点，可打开对局详情。页面时间统一使用 **UTC+8**。

在对局详情中点击队员名称，可查看该场次保存的名片、徽章和工服。图片首次查看时下载并缓存；已缓存图片可离线查看。

### 趋势对比与图表导出

**分项趋势：**

1. 点击 **查看详细趋势**。
2. 按需切换 **数量 / 占比**，并选择疑似组队队友。
3. 按需开启团队合计、25% 参考线或人名标签。
4. 展开 **场次筛选与导出**。
5. 选择起始场次、结束场次和导出内容。
6. 点击 **导出 PNG** 或 **导出 SVG**。

数量图的 25% 参考线表示每场四人合计除以 4。占比图使用固定的 25% 水平线。它们用于比较贡献分布，不代表及格标准。

导出图片保留所选范围、玩家、刻度、参考线和图例。可单独导出一个指标，也可将三张图导出为长图。

**分数变化：** 在总览切换到 **分数变化**，使用图表右下角的导出按钮。图片包含本期地图、时间范围、已保存场次说明、分数标注和图例。这里的分数是段位分数，不是打工奖励点数。

灰色空心圆表示掉线。表现图在零刻度显示掉线标记，分数图显示已有的实际结束分数。统计口径见文末。

### 停止与再次启动

关闭网页仅结束查看。需要停止后台服务时，在安装目录执行以下命令；自定义项目名请替换 `salmon-review`：

```powershell
docker compose -p salmon-review stop
```

再次使用时，先启动 Docker Desktop，再运行 **`Start.cmd`**。使用自定义项目名或端口时，应继续传入原参数。新版启动器会保留网页更新已安装的较高版本。

## 四、导入已有文件

已有 nxapi 导出文件时，可在 **数据与同步 → 导入已有记录** 中选择 JSON 文件，无需先连接账号。

| 文件名 | 内容 |
| --- | --- |
| `splatnet3-coop-result-*.json` | 单场打工的详细结算 |
| `splatnet3-coop-summary-*.json` | 排班与场次列表，用于归类和判断记录完整性 |

建议同时导入两类文件。只有详情时可先保存，之后补充汇总。导入顺序不限，重复记录会自动去重。

每批最多选择 2000 个 JSON 文件，总大小建议小于 60 MB。较多记录请分批导入。缺少关键字段或不支持的模式会列入“暂未纳入统计的记录”。

装备文件 `gear.json` 不属于打工记录，不能导入。其他工具的导出格式不保证兼容。`examples/` 包含虚构演示记录，只应导入独立测试实例，以免绑定错误玩家。

## 五、备份、迁移与升级

### 备份与恢复

在 **数据与同步 → 备份与恢复** 中点击 **下载数据备份**。建议定期备份，并在升级或迁移前另存一份。

网页备份包含原始战绩、排班汇总和玩家昵称，不包含登录凭据、自动同步设置或图片缓存。请妥善保存，不要公开上传。

迁移到另一台电脑时：

1. 在新电脑安装并启动程序。
2. 在 **备份与恢复** 中选择备份文件。
3. 点击 **恢复并合并**。
4. 重新连接同一个任天堂账号。
5. 按需重新设置自动同步。

恢复只增加缺少的记录，不覆盖已有记录。网页恢复上限约为 60 MB，超大单个备份暂不支持网页恢复。

### 网页更新

**从 0.3.9 及更早版本升级时，必须使用 0.3.10 或更新版本的完整安装包过渡一次。** 完成后，主程序和更新组件均支持网页一键更新。请保留 0.3.10 或更新版本的启动器。

1. 按 [网页更新说明](UPDATING.md)准备自己的 GitHub 访问令牌。
2. 打开 **数据与同步 → 版本与更新**。
3. 在 **GitHub 更新权限** 中验证并保存令牌。
4. 点击 **检查更新**。
5. 阅读版本说明，点击更新按钮。

程序会在打开网页时检查新版，但不会自动安装。签名校验和下载阶段可取消更新，取消后可重试。进入安装或恢复阶段后，请保持 Docker Desktop 运行并等待完成。

更新会保留原数据卷，并在安装失败时尝试恢复旧版。若提示“自动恢复未完成”，请保留容器和数据卷，按提示联系维护者。备份与旧镜像的保留规则见 [网页更新说明](UPDATING.md#取消更新与磁盘占用)。

### 使用完整安装包升级

1. 下载数据备份。
2. 记录原 Compose 项目名和端口。
3. 将新版 Windows 安装包完整解压到新目录。
4. 如有旧 `.env`，将其复制到新目录。
5. 使用新版启动器，沿用原项目名和端口。

例如，原项目名为 `salmon-review-dev`：

```powershell
.\Start.cmd -ProjectName salmon-review-dev
```

如需指定端口：

```powershell
.\Start.cmd -ProjectName salmon-review-dev -Port 8788
```

`-Port` 仅作用于本次启动。后续启动需使用同一参数，或在安装目录的 `.env` 中保存 `SALMON_PORT=8788`。使用该端口时，访问 `http://127.0.0.1:8788/`。

同一项目会沿用原数据卷，无需再次导入战绩。更新完成后刷新浏览器；界面未更新时按 `Ctrl + F5`。

**不要删除数据卷，也不要执行 `docker compose down -v`。** 重置 Docker Desktop 也可能删除本地记录。复制安装目录不能代替数据备份。

## 六、诊断与常见问题

### 一键诊断

打开 **数据与同步 → 一键诊断与导出**，检查本地服务、数据库、可用空间、战绩读取和同步／更新状态。可以取消、重新诊断，或导出已完成的结果。

**导出诊断信息** 会下载本机 JSON 文件，不会自动上传。报告不包含令牌、昵称、原始战绩、文件路径或原始日志。诊断不会触发上游同步，也不能证明当前上游网络或登录凭据有效。

如果整个网页无法打开，请先检查 Docker Desktop 和应用容器。

### 常见问题

| 问题 | 处理方法 |
| --- | --- |
| 找不到 `docker`，或无法连接 Docker 引擎 | 确认 Docker Desktop 已安装且引擎正在运行，再重新启动程序。 |
| 找不到配置文件 | 在包含 `compose.yaml` 的安装目录打开终端。 |
| 安装时出现 build、npm 或 Docker Hub 下载 | 核对是否下载了 Windows 发行包，并使用包内的 `Start.cmd`。 |
| 镜像文件缺失或校验失败 | 重新下载并完整解压安装包，避免混用不同版本的文件。 |
| 提示发现已有项目 | 用 `Start.cmd -ProjectName 原项目名` 启动。 |
| 端口被占用 | 在 Docker Desktop 中检查是否已有实例运行；需要时使用 `-Port` 指定空闲端口。 |
| 浏览器无法访问 | 核对本地地址及端口，执行 `docker compose -p salmon-review ps` 检查服务状态。 |
| 页面样式缺失或仍显示旧版 | 先按 `Ctrl + F5`；仍有异常时检查容器状态和安装包版本。 |
| 登录链接无效或过期 | 重新生成链接，并复制任天堂页面上“选择此账号”按钮的链接地址。 |
| `Remote configuration prevents Coral authentication` 或 f-generation 服务不可用 | 检查 nxapi 上游服务状态，稍后重试；该提示不一定表示密码错误。 |
| 账号已连接但同步失败 | 查看具体提示：认证失效时重新连接；网络错误或限流时按提示等待。 |
| 更新后没有记录 | 核对项目名是否改变。保留旧数据卷，使用原项目名重新启动。 |
| 账号与已有战绩不一致 | 连接该实例已绑定的玩家账号。不要混用其他玩家或演示记录。 |
| 记录少于实际场次 | 检查“暂未纳入统计的记录”；上游已不再提供的历史场次可能无法补回。 |
| 手机或其他电脑无法访问 | 当前版本只供安装它的电脑使用，`127.0.0.1` 不指向其他设备。 |

需要检查日志时，在安装目录执行：

```powershell
docker compose -p salmon-review logs --tail=100 app
```

反馈问题时，请提供版本、系统、操作步骤和错误提示。不要提交令牌、授权返回链接、登录缓存或完整数据卷。敏感安全问题按 [安全说明](SECURITY.md)报告。

## 技术细节

### 数据来源与组件

| 组件 | 用途 |
| --- | --- |
| Nintendo / SplatNet 3 | 提供原始打工结算及记录引用的游戏图片。 |
| [nxapi](https://github.com/samuelthomas2774/nxapi) `1.6.1-next.257` | 提供非官方命令行工具，负责认证、凭据缓存、令牌刷新和记录下载。 |
| nxapi 远程配置与第三方认证服务 | 提供 Nintendo Switch Online 认证所需的 f-generation 服务；服务选择由 nxapi 的远程配置控制。 |
| Node.js `22.23.2` 与内置 SQLite | 运行本地服务，保存原始记录和统计数据。 |
| undici `6.28.1` | 处理 HTTP 请求。 |
| Docker / Compose | 运行主程序、更新组件并管理数据卷。 |

程序调用 nxapi 的原始 CLI，不自行重写其认证流程，也不调用 s3s 或观星网站的接口。登录引导参考了 [Cypas/splatoon3-nso](https://github.com/Cypas/splatoon3-nso)，页面示意由本项目绘制。

### 网络通信与本地存储

认证需要访问任天堂和 nxapi 使用的第三方服务。nxapi 会向第三方认证服务发送短期令牌、账号标识等必要字段。具体服务和字段取决于固定依赖版本及远程配置，参见 [nxapi 认证说明](https://github.com/samuelthomas2774/nxapi#coral-client-authentication)。

同步请求发送到任天堂。游戏图片从记录引用的 Nintendo 资源域名下载并缓存。网页更新访问原私有 GitHub 仓库。本项目不提供战绩上传服务器，也不自动上传记录到 stat.ink 或 AI 服务。

| 数据卷 | 保存内容 |
| --- | --- |
| `<项目名>_salmon-data` | SQLite 数据库、原始记录、下载文件、图片缓存和任天堂登录缓存；容器内路径为 `/data`。 |
| `<项目名>_salmon-updates` | GitHub 更新凭据、更新状态、下载文件和更新前备份；容器内路径为 `/updates`。 |

本地凭据有文件访问权限限制，但没有额外加密。有本机管理员或 Docker 权限的人可能读取这些内容。更新前备份包含凭据，与网页导出的战绩备份不同，不应分享。

退出任天堂账号会删除登录缓存并关闭自动同步，已保存战绩仍保留。主程序默认仅绑定宿主机 `127.0.0.1`；更新组件不开放主机端口。当前版本不支持公网、局域网或反向代理下的多人部署。

### 统计口径

- **搬蛋：** 个人搬蛋与协助分开；均值、趋势和占比不计协助。
- **击杀：** 指巨大鲑鱼击杀。对局团队击杀取敌人明细中的击倒数合计；趋势图的四人合计取四名玩家的个人结算之和。
- **被救援次数：** 取个人结算值，不等同全部倒地次数。
- **通过：** 指常规三波通过。头目加赛单独展示，平均通过波次不包含加赛。
- **占比：** 以当场四人的同项个人结算合计为分母，隐藏队友不改变分母。有效结算中全队为 0 时，按 0% 展示并连接。
- **掉线：** 无波次且结果代码为 `-1` 的记录单独保存，不计入正常结算场数、场均表现或通过率。表现曲线经过零刻度的灰色空心标记，但不将其作为真实零值结算。缺场、结算缺失或玩家缺席仍会断线。
- **疑似组队：** 在确认连续的记录内，按玩家身份识别同队至少 3 场的队友。掉线不打断判断，也不增加有效场数；缺场、队友离队或无法确认相邻时中断判断。
- **个人纪录：** 仅统计本期已保存的有效结算。并列取首次；最长连胜遇到失败、掉线或未确认连续时重新计数。

游戏结算中的团队搬蛋与个人搬蛋合计可能不同，程序保留各自口径。常规失败场次中的特殊武器剩余提示只表示武器未用完，不用于判定失败责任。其他模式或关键字段缺失的记录会保留原始数据，并说明排除原因。

### 手动启动与源码运行

以下命令用于从完整发行包首次手动启动 Linux/amd64 容器：

```sh
docker load -i salmon-review-image.tar.gz
docker compose -p salmon-review up -d --no-build --pull never
docker compose -p salmon-review ps
```

确认服务状态为 `healthy` 后访问本地页面。网页更新后，旧 `compose.yaml` 可能仍指定旧镜像；Windows 用户应使用新版启动器重启，避免降级。

从源码构建使用独立配置，需要访问 Docker 镜像仓库和 npm：

```powershell
docker compose -p salmon-review-dev -f compose.yaml -f compose.build.yaml up -d --build
```

直接运行源码需要 Node.js `22.23.2`：

```sh
npm ci --ignore-scripts
npm test
npm run check
npm start
```

`DATA_DIR` 指定数据目录，`PORT` 指定端口。直接运行默认监听 `127.0.0.1`；容器内监听 `0.0.0.0`，访问范围由 Compose 的端口绑定限制。该 Node.js 版本的内置 SQLite 仍标为 experimental。

### 同步与更新实现

认证使用 `nxapi nso auth --select`。记录下载使用 `nxapi splatnet3 dump-results <目录> --coop --no-battles --auto-update-session`。后端校验授权返回链接的 `state`，再通过标准输入传给 CLI；授权链接不写入命令参数，CLI 原始输出不直接返回网页或应用日志。

进程适配器将 SplatNet 3 数据请求的 `Accept-Language` 固定为 `zh-CN`，不修改账号语言、地区或 nxapi 认证流程。既有原始记录不会因升级自动改写。

每个实例同时只运行一个同步任务，最长 15 分钟。导入、恢复和退出账号不能与同步并行。重启后未结束的任务标记为中断；已下载记录保留供后续归档。

数据库格式当前为 v1。程序拒绝打开高于其支持版本的数据库。格式变更需要显式迁移和测试。

网页更新使用签名清单、镜像校验和同项目临时助手，同时替换主程序与更新组件。两个组件通过检查后才提交；未提交的失败或中断按事务记录恢复。更新组件具有 Docker 控制权限，应仅安装可信维护者提供的版本。实现与恢复约定见 [UPDATING.md](UPDATING.md)。
